## 1. 핵심 질문 답변

> 검색한 문장을 붙여넣지 말 것. 본인 문장으로 쓰고, 예시 코드를 곁들이면 좋음.

### Q1. `equals`만 재정의하고 `hashCode`는 그대로 두면, 그 객체를 `HashMap` 키로 썼을 때 무슨 일이 벌어지는가?

계속 해시 코드가 달라져서 같은 버킷에 담지 못하게 됨  
그래서 이미 버킷에 있음에도 불구하고, 그 버킷을 찾지 못해 null을 반환하는 사태가 발생함

### Q2. `HashMap` 키로 **가변 객체**를 쓰면 안 되는 이유는? (필드를 바꾸면 어떻게 되는가)

HashMap에 가변 객체를 저장한 후 그 객체의 값을 바꾸게되면, 그 객체의 해시 코드도 바뀌게 됨  
HashMap은 해시 코드가 변했다는 사실을 모르니 그대로 냅두게 됨  
그러니 해시 코드가 달라 그 버킷을 찾지 못하게 되고, 영영 조회할 수 없게 되는 것

### Q3. 모든 키의 `hashCode`가 같다면 조회 시간복잡도는 어떻게 되는가? 자바 8 이후에는?

LinkedList를 처음부터 순회해야 하므로 `O(N)`의 시간 복잡도를 가지게 됨  
Java 8부터는, 내부 조건을 충족해서 레드-블랙 트리로 바뀐다면 `O(log N)`의 시간 복잡도를 가지게 됨

### `hashCode()`가 **항상 0을 리턴**하는 클래스를 만들어 키로 넣고, 정상 클래스와 조회 성능을 비교하세요.

정상: 1ms  
비정상: 3807ms  
진짜 끔찍하게 차이남

## 3. 구현 과제 회고

- 어떻게 설계했는가  
  DK의 HashMap 구조를 참고하며 내 눈에 좀 더 익는 구조로 설계해보도록 노력함
- 막혔던 지점  
  해시함수를 어떻게 설계해야할지 감이 안잡혀서 AI의 도움을 받음. 이게 맞는지도 잘 모르겠음..
- JDK 실제 구현과 비교했을 때 다른 점  
  JDK에서는 레드-블랙 트리같은 최적화나 다양한 환경에서 문제 없이 사용할 수 있도록 다양한 로직이 들어가있었음  
  나야 그냥 레드-블랙 트리를 쓰면 시간복잡도가 좋아진다더라 수준으로 알고있지만, 아무것도 모르는 상태에서 이런 경우에는 이 자료구조를 써야겠군 하고 알아내는 과정이 어렵겠다 싶었음  
  이런걸 아무것도 베이스 없는 상태에서 처음부터 설계해서 만든다는게 신기하다
