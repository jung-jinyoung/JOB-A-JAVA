> 학습 리스트

### 1. `HashMap` / `LinkedHashMap` / `TreeMap` — 순서와 복잡도

Python은 3.7부터 `dict`에서 데이터 삽입 순서를 보장하기 때문에 "순서 보장된 출력" 요구사항이 하나로 처리가 가능하다.

Java에서는 똑같이 `HashMap`을 쓰면 순서가 보장되지 않아 요구사항을 구현하기 싫다.

크게 보면 Java에서 Map은 아래의 이미지처럼 크게 파생되어 구분할 수 있다.

![Java-Map-Class](https://velog.velcdn.com/images/sweet_sumin/post/126632d7-2ca4-47bd-84dd-af08301cde63/image.png)

`HashMap`은 키의 해시값이 위치를 정하고 (그래서 버킷 배열에 순서대로 저장되지 않는다), `TreeMap`은 키끼리의 비교가 자리를 정한다. `LinkedHashMap`은 위의 분류 이미지처럼 `HasMap`과 똑같이 해시로 저장되는 위치를 정하지만, 넣은 순서대로 항목들을 엮게되어 삽입 순서를 보장할 수 있다.

이러한 특성 때문에 세 가지 컬렉션의 순서와 비교도는 아래의 표처럼 저장할 수 있다.

| 항목                     | HashMap              | LinkedHashMap                | TreeMap                                |
| ------------------------ | -------------------- | ---------------------------- | -------------------------------------- |
| **자리를 정하는 것**     | 키의 해시값          | 키의 해시값 (동일)           | 키끼리의 비교(`compareTo`)             |
| 내부 구조                | 버킷 배열            | 버킷 배열 + 이중 연결 리스트 | 레드-블랙 트리                         |
| **순회 순서**            | 보장 없음            | 삽입 순서                    | 키의 정렬 순서                         |
| `put` / `get` / `remove` | O(1) 평균            | O(1) 평균                    | O(log n)                               |
| 최악의 경우              | 해시 충돌 시 저하    | 해시 충돌 시 저하            | O(log n) 보장                          |
| 전체 순회                | O(n), 빈 버킷도 훑음 | O(n), 링크만 따라감          | O(n)                                   |
| 정렬된 순회              | 별도 정렬 O(n log n) | 별도 정렬 O(n log n)         | O(n) (추가 비용 없음)                  |
| 범위 / 근접 탐색         | 불가                 | 불가                         | O(log n) (`floorKey`, `ceilingKey` 등) |
| `null` 키                | 1개 허용             | 1개 허용                     | 불가                                   |
| 추가 비용                | 기준                 | 항목당 참조 2개만큼 메모리 ↑ | 키 비교 연산 비용                      |

### 2.`HashSet`은 사실 `HashMap`이다

Python에서의 set과 가장 가까운 것이 `HashSet`이며, 사용은 아래와 같다.

```java
Set<String> visited = new HashSet<>();
//└ 약속으로 선언        └ 구현으로 생성
```

먼저 `Set` 의 특징을 세 가지로 정리해보면,

1. 중복이 없다
2. 순서 보장이 안된다. (HashSet 특징)
3. 인덱스가 없다.

<hr/>

HashSet 내부 코드는 아래와 같이 생겼다.

```java
public class HashSet<E> ... {
    private transient HashMap<E, Object> map;          // 진짜 저장소
    private static final Object PRESENT = new Object(); // 값 자리를 채울 더미

    public boolean add(E e) {
        return map.put(e, PRESENT) == null;
    }
    public boolean contains(Object o) {
        return map.containsKey(o);
    }
}

```

`HashSet`은 내부적으로 `HashMap`을 사용해 데이터를 저장하기 때문에 Hash Table과 유사한 자료구조로 데이터를 저장한다고 할 수 있다.  
`HashMap`은 key-value 형태로 데이터를 저장하지만, key값으로 사용되는 객체 자체만 필요하다.

따라서 `HashMap` 구조를 그대로 활용하는 이유는 `Set` 자료구조를 사용하는 목적인는'중복없이 데이터 저장하기'을 해시 테이블 코드를 두 번 만드지 않아도 되기 때문이다.

### 3.`ArrayDeque` vs `LinkedList` — 왜 큐/스택에 `ArrayDeque`를 권하는가

Python의 `deque`를 `ArrayList`로 큐를 구현해 BFS를 진행한다면

```java
    List<Integer> queue = new ArrayList<>();
    queue.add(start);
    while (!queue.isEmpty()) {
        int cur = queue.remove(0);   // 맨 앞에서 꺼내기
        ...
    }
```

인데, 배열이라 `remove`로 뒤에 있는 원소를 전부 한 칸씩 앞으로 당겨야 하는 복잡도 O(n)이 발생한다.

하지만 DFS를 구현에는 맨 뒤에서 꺼내니 O(1)로 해결할 수 있다.

즉 `ArrayList`로 스택은 가능하나, 큐는 복잡도로 힘들 수도 있다.  
이렇게 큐, 스택 구분하여 클래스를 두는 대신 Java에서는 `ArrayDeque`으로 복잡도 O(1)로 양 끝에 접근하여 문제를 해결한다.

```markdown
Collection (인터페이스)
└─ Queue (인터페이스) 한쪽 끝만 — offer / poll / peek
└─ Deque (인터페이스) 양쪽 끝 — addFirst/addLast, pollFirst/pollLast
├─ ArrayDeque ← 배열 기반 (권장)
└─ LinkedList ← 연결 리스트 기반
```

인터페이스 계층은 위와 같고 활용 방법은 아래와 같다.

```java
Queue<Integer> q = new ArrayDeque<>();   // 큐로만 쓸 거면 Queue로 선언
Deque<Integer> dq = new ArrayDeque<>();  // 양쪽 끝 다 쓸 거면 Deque로
```

Python `deque.pop()`은 뒤에서 빼는데, Java `Deque.pop()`은 앞에서 뺀다는 차이가 있다.

Java6에 추가된 `ArrayDeque` 등장 이전에는, `Queue`를 `LinkedList`로 구현했다. 시간복잡도는 두 구조 모두 양 끝 삽입,삭제 O(1)로 해결할 수 있다.

차이는 "데이터가 메모리에 어떻게 놓이는가"에 있다.

`ArrayDeque`는 배열 하나 안에 원소가 연속으로 있고, `LinkedList`는 원소마다 Node객체가 따로 생기게 된다. CPU는 값 하나를 읽을 때 그 값 주면 메모리를 캐싱하므로, 연속으로 놓인 쪽이 더 효율적이다. 따라서 `ArrayDeque`는 다음 위치의 데이터에 접근할 때 더 유리하다.

또한 `LinkedList`는 값 하나를 담기 위해 item, next, prev 참조 세 개를 쓰게 되니 상대적으로 메모리 소모도 많다.

즉 두 가지를 사용했을 때 복잡도는 같지만, `ArrayDeque`는 배열 하나에 연속으로 담기고 `LinkedList`는 노드 객체가 힙에 흩어지기 때문에 실제 실행 속도와 메모리 사용량에서 차이가 난다.
