# 재귀와 콜 스택

## 1. 메서드 호출과 스택 프레임

자바에서 메서드를 호출하면 JVM의 콜 스택에 해당 호출을 위한 **스택 프레임**이 생성된다.

스택 프레임에는 주로 다음 정보가 들어간다.

- 메서드의 매개변수와 지역 변수
- 연산 과정에서 사용하는 임시 값
- 메서드 실행이 끝난 뒤 돌아갈 위치
- 현재 메서드 호출의 실행 상태

지역 변수가 객체를 담고 있다면 객체 자체는 일반적으로 힙에 저장되고, 스택 프레임에는 그 객체를 가리키는 참조값이 저장된다. 이 참조값은 `hashCode()` 값과는 다른 개념이다.

```java
static void greet(String name) {
    int count = 1;
    String message = "Hello " + name;
}
```

위 메서드가 실행될 때 `count`의 값과 `name`, `message`의 참조값은 `greet`의 스택 프레임에 들어간다. `name`과 `message`가 가리키는 문자열 객체는 힙에 존재한다.

## 2. 재귀 호출이 쌓이고 반환되는 과정

재귀는 메서드가 자기 자신을 다시 호출하는 방식이다. 일반 메서드 호출과 마찬가지로 재귀 호출마다 새로운 스택 프레임이 생긴다.

```java
static int factorial(int n) {
    if (n == 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

`factorial(3)`을 실행하면 호출 순서는 다음과 같다.

```text
factorial(3) → factorial(2) → factorial(1)
```

각 호출의 스택 프레임은 아래와 같이 쌓인다.

```text
위쪽  factorial(1): n = 1
      factorial(2): n = 2
아래쪽 factorial(3): n = 3
```

`factorial(1)`이 종료 조건에 도달하면 가장 나중에 생성된 프레임부터 제거되며 결과가 반환된다.

```text
factorial(1) = 1
factorial(2) = 2 * 1 = 2
factorial(3) = 3 * 2 = 6
```

따라서 호출 순서는 `3 → 2 → 1`, 반환 순서는 `1 → 2 → 3`이다. 콜 스택은 가장 나중에 들어온 것이 가장 먼저 나오는 **LIFO(Last In, First Out)** 구조이다.

## 3. 종료 조건과 StackOverflowError

재귀 함수에는 호출을 멈추는 종료 조건이 필요하다.

```java
static void recurse(int n) {
    System.out.println(n);
    recurse(n + 1);
}
```

위 코드는 종료 조건이 없기 때문에 앞선 호출이 끝나지 않은 상태에서 다음 호출이 계속 발생한다. 스택 프레임이 제거되지 않고 계속 쌓이다가 사용할 수 있는 스택 공간을 모두 소모하면 `StackOverflowError`가 발생한다.

종료 조건이 코드에 존재하는 것만으로는 충분하지 않다. 매번 재귀 호출을 할 때 종료 조건에 가까워져야 한다.

```java
static void countdown(int n) {
    if (n == 0) {
        return;
    }

    System.out.println(n);
    countdown(n + 1); // 양수에서 시작하면 0에서 계속 멀어진다.
}
```

양수 `n`을 전달하면 `n`이 계속 커지므로 종료 조건인 `n == 0`에 도달하지 못한다. 다음처럼 `n - 1`을 전달해야 종료 조건에 가까워진다.

```java
static void countdown(int n) {
    if (n == 0) {
        return;
    }

    System.out.println(n);
    countdown(n - 1);
}
```

## 4. 재귀 깊이의 한계

가능한 최대 재귀 깊이는 항상 같은 숫자로 정해져 있지 않다. 주로 다음 요소에 따라 달라진다.

- 각 스레드에 할당된 스택 메모리의 크기
- 메서드 호출마다 만들어지는 스택 프레임의 크기
- JVM의 실행 환경과 스택 크기 설정(`-Xss`)

지역 변수와 실행 상태가 많아 스택 프레임 하나가 커지면, 같은 스택 크기에서도 더 적은 호출만 쌓을 수 있다. `-Xss`로 스택 크기를 키울 수 있지만 이는 한계를 뒤로 미루는 방법일 뿐, 아주 깊은 재귀를 근본적으로 안전하게 만들지는 않는다.

## 5. 깊은 재귀를 반복으로 바꾸기

호출 깊이가 100만처럼 매우 크다면 재귀보다 반복문이 안전하다.

```java
static int factorialLoop(int n) {
    int result = 1;

    for (int i = 2; i <= n; i++) {
        result *= i;
    }

    return result;
}
```

DFS처럼 앞으로 처리할 위치를 직접 기억해야 한다면 `ArrayDeque`를 명시적인 스택으로 사용할 수 있다.

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(start);

while (!stack.isEmpty()) {
    int current = stack.pop();
    // current 처리
}
```

JVM의 콜 스택에 실행 상태를 맡기는 대신, 프로그램이 처리할 값을 직접 자료구조에 보관하는 방식이다.
