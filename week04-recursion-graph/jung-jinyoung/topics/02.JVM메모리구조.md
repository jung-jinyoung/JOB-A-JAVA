# JVM 메모리 구조

## 1. 전체 구조

JVM 메모리의 기본 영역은 스택, 힙, 메타스페이스로 구분할 수 있다.

```text
JVM 메모리
├─ 스택: 현재 실행 중인 메서드의 작업 공간
├─ 힙: 객체와 배열의 실제 데이터가 저장되는 공간
└─ 메타스페이스: 클래스의 구조와 메서드 정보가 저장되는 공간
```

- **스택**: 메서드 호출마다 만들어지는 작업 공간이다.
- **힙**: `new`로 생성한 객체와 배열이 저장되는 공간이다.
- **메타스페이스**: JVM이 클래스 정보를 저장하는 공간이다.

---

## 2. 스택과 힙

```java
static void register() {
    int age = 20;
    Person person = new Person("Jin");
}
```

```text
스택                              힙

register() 스택 프레임
├─ age: 20
└─ person: 참조값 ─────────────▶ Person 객체
                                  └─ name: 참조값 ──▶ "Jin" 객체
```

- 원시 타입 지역 변수 `age`의 값은 스택 프레임에 저장된다.
- 지역 변수 `person`에는 객체 자체가 아니라 객체를 가리키는 참조값이 저장된다.
- `new Person(...)`으로 생성한 실제 객체는 힙에 저장된다.
- 메서드가 끝나면 해당 스택 프레임과 지역 변수는 사라진다.
- 지역 변수가 사라져도 객체를 가리키는 다른 참조가 있다면 힙 객체는 계속 살아 있다.

> 지역 변수의 생명주기와 그 변수가 가리키는 객체의 생명주기는 같지 않다.

---

## 3. 메타스페이스

**메타스페이스는 JVM이 클래스 정보를 저장하는 공간이다.**

```java
class Person {
    String name;

    void greet() {
        System.out.println(name);
    }
}
```

```text
메타스페이스                       힙

Person 클래스 정보                 Person 객체 1
├─ 클래스 이름: Person             └─ name → "Jin"
├─ String name 필드가 있음
└─ greet() 메서드가 있음           Person 객체 2
                                    └─ name → "Kim"
```

- 메타스페이스에는 `Person` 클래스가 어떻게 구성되어 있는지에 대한 정보가 저장된다.
- 힙에는 `Person` 클래스로 만든 객체마다 실제 값이 저장된다.
- 클래스 정보는 객체를 만들기 위한 설계 정보이고, 객체는 그 설계를 바탕으로 만든 실제 데이터이다.

### 런타임 상수 풀

메타스페이스의 클래스 메타 데이터에 저장되는 **런타임 상수 풀은 클래스가 실행 중 사용할 값과 클래스·필드·메서드를 찾기 위한 정보 표이다.**

예를 들어 `System.out.println("Hello")`를 실행하려면 JVM은 `System` 클래스, `out` 필드, `println` 메서드 등에 대한 정보를 찾아야 한다. 런타임 상수 풀은 이러한 대상을 찾고 연결하는 데 사용된다.

** 참고 사항 **

- **Method Area**: JVM 명세에서 클래스 정보를 저장하기 위한 공간을 가리키는 논리적 개념이다.
- **Metaspace**: HotSpot JVM이 클래스 메타데이터를 저장하기 위해 사용하는 실제 구현 영역이다.

## 4. GC

**GC(Garbage Collection)는 더 이상 사용할 수 없는 힙 객체를 찾아 메모리에서 정리하는 기능이다.**

객체가 GC 대상인지 판단하는 기준은 참조의 개수가 아니라 **GC Root에서 객체까지 도달할 수 있는가**이다.

**GC Root는 JVM이 객체의 생존 여부를 확인할 때 탐색을 시작하는 출발점이다.** 실행 중인 메서드의 지역 변수, 사용 중인 `static` 참조 등이 출발점이 될 수 있다.

```text
GC Root
  │
  ▼
객체 A ──▶ 객체 B       객체 C ──▶ 객체 D

A, B: 도달 가능          C, D: 도달 불가능
      → 생존                  → GC 대상
```

GC 대상이 되었다고 즉시 회수되는 것은 아니다. JVM이 GC를 실행할 때 회수될 수 있다.

### GC 대상 판단 후보 정리

#### 1. 참조에 `null` 대입

```java
Person person = new Person("Jin");
person = null;
```

다른 참조가 없다면 `Person("Jin")` 객체에 도달할 수 없으므로 GC 대상이다.

#### 2. 메서드 종료

```java
static void create() {
    Person person = new Person("Jin");
}
```

메서드가 끝나면 `person`은 스택 프레임과 함께 사라진다. 다른 참조가 없다면 객체도 GC 대상이 된다.

#### 3. 다른 곳으로 참조 전달

```java
static Person saved;

static void create() {
    Person person = new Person("Jin");
    saved = person;
}
```

메서드가 끝나 지역 변수 `person`은 사라지지만, `saved`를 통해 객체에 계속 도달할 수 있으므로 GC 대상이 아니다.

#### 4. 객체끼리 순환 참조

두 객체가 서로 참조해도 GC Root에서 두 객체로 도달할 방법이 없다면 모두 GC 대상이다.

## 5. 메모리 - Young 영역과 Old 영역

대부분의 객체는 생성된 후 오래 살아남지 못한다. JVM은 이 특성을 이용하여 힙을 세대별로 관리한다.

```text
Heap
├─ Young Generation: 새로 생성된 객체가 주로 저장되는 영역
│  ├─ Eden: 새 객체가 처음 생성되는 공간
│  └─ Survivor: GC에서 살아남은 객체가 머무르는 공간
│
└─ Old Generation: 여러 번의 GC에도 살아남은 객체가 이동하는 영역
```

### Minor GC

**Minor GC는 Young 영역을 중심으로 사용하지 않는 객체를 정리하는 GC이다.**

- 비교적 자주 발생한다.
- 살아남은 객체는 Survivor 영역으로 이동할 수 있다.
- 계속 살아남은 객체는 Old 영역으로 승격될 수 있다.

### Major GC

**Major GC는 Old 영역을 중심으로 객체를 정리하는 GC이다.**

- 일반적으로 Minor GC보다 덜 자주 발생한다.
- 검사할 영역과 살아 있는 객체가 많아 일반적으로 비용이 더 크다.
- GC 구현에 따라 `Major GC`와 `Full GC` 용어의 정확한 의미는 달라질 수 있다.

```text
객체 생성
   ▼
Young의 Eden
   ▼ Minor GC에서 생존
Survivor
   ▼ 여러 번 생존
Old로 승격
```

## 6. GC가 있어도 메모리 누수가 발생하는 이유

**자바의 메모리 누수는 사용하지 않는 객체를 불필요하게 계속 참조하여 GC가 회수하지 못하는 상태이다.**

```java
static final List<Person> cache = new ArrayList<>();

static void add(Person person) {
    cache.add(person);
}
```

객체를 실제 업무에서는 더 이상 사용하지 않더라도 `cache`가 계속 참조하면 GC 관점에서는 도달 가능한 객체이다. 따라서 GC 대상이 되지 않는다.

```text
개발자 관점: 더 이상 필요 없는 객체
GC 관점: GC Root에서 도달 가능한 객체
결과: 회수되지 않아 메모리 누수 가능
```

필요 없어진 참조는 컬렉션에서 제거하거나 `clear()` 등을 통해 정리해야 한다.

---

## 7. 핵심 정리

1. 스택은 현재 실행 중인 메서드의 작업 내용을 저장한다.
2. 힙은 객체와 배열의 실제 데이터를 저장한다.
3. 메타스페이스는 클래스의 구조와 메서드 정보를 저장한다.
4. 메서드가 끝나면 지역 변수는 사라지지만, 힙 객체는 다른 참조가 있으면 살아남는다.
5. GC는 GC Root에서 도달할 수 없는 힙 객체를 회수한다.
6. 새 객체는 주로 Young에서 시작하고, 오래 살아남으면 Old로 승격될 수 있다.
7. Minor GC는 Young 영역을, Major GC는 Old 영역을 중심으로 정리한다.
8. 필요 없는 객체에 대한 참조를 계속 유지하면 GC가 있어도 메모리 누수가 발생할 수 있다.
