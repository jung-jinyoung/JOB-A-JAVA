# 힙과 정렬된 컬렉션

## 1. 이진 힙

이진 힙은 다음 조건을 만족하는 자료구조다.

1. 위에서 아래로, 왼쪽부터 채워지는 완전 이진 트리다.
2. 부모와 자식 사이에 일정한 대소 관계가 있다.

최소 힙에서는 부모가 자식보다 작거나 같다.

```text
부모 ≤ 자식
```

```text
        1
      /   \
     3     2
    / \   /
   7   9 8
```

최소 힙의 루트에는 항상 전체 최솟값이 있다.

하지만 형제나 서로 다른 가지의 순서는 보장하지 않는다. 따라서 힙 전체가 정렬된 것은 아니다.

## 2. 배열로 힙 표현

완전 이진 트리는 중간에 빈자리가 없으므로 배열로 표현할 수 있다.

```text
        1
      /   \
     3     2
    / \   /
   7   9 8
```

```text
값:      [1, 3, 2, 7, 9, 8]
인덱스:   0  1  2  3  4  5
```

현재 노드의 인덱스를 `i`라고 하면:

```java
int leftChild = 2 * i + 1;
int rightChild = 2 * i + 2;
int parent = (i - 1) / 2;
```

## 3. siftUp

`siftUp`은 힙에 새로운 원소를 삽입할 때 최소 힙 조건을 복구하는 작업이다.

```text
1. 새 값을 배열의 마지막에 추가한다.
2. 새 값과 부모를 비교한다.
3. 새 값이 부모보다 작으면 교환한다.
4. 부모보다 크거나 같거나 루트에 도달할 때까지 반복한다.
```

예를 들어 다음 최소 힙에 `2`를 추가한다.

```text
기존: [1, 3, 5, 7, 9, 8]
추가: [1, 3, 5, 7, 9, 8, 2]
```

`2`의 부모는 `5`다.

```text
2 < 5
```

두 값을 교환한다.

```text
[1, 3, 2, 7, 9, 8, 5]
```

이제 부모 `1`과 비교한다.

```text
2 ≥ 1
```

최소 힙 조건을 만족하므로 종료한다.

완전 이진 트리의 높이만큼 올라갈 수 있으므로 시간복잡도는 `O(log n)`이다.

## 4. siftDown

`siftDown`은 최소 힙의 루트를 제거한 뒤 힙 조건을 복구하는 작업이다.

```text
1. 루트의 최솟값을 제거한다.
2. 배열의 마지막 값을 루트로 옮긴다.
3. 두 자식 중 더 작은 자식을 선택한다.
4. 현재 값이 선택한 자식보다 크면 교환한다.
5. 자식보다 작거나 같거나 마지막 층에 도달할 때까지 반복한다.
```

예:

```text
기존:       [1, 3, 2, 7, 9, 8, 5]
루트 제거:  [_, 3, 2, 7, 9, 8, 5]
마지막 이동: [5, 3, 2, 7, 9, 8]
```

루트 `5`의 자식 `3`, `2` 중 더 작은 `2`와 교환한다.

```text
[2, 3, 5, 7, 9, 8]
```

`5`는 자식 `8`보다 작으므로 종료한다.

최악에는 루트부터 마지막 층까지 내려가므로 시간복잡도는 `O(log n)`이다.

## 5. PriorityQueue

Java의 `PriorityQueue`는 기본적으로 최소 힙으로 동작한다.

```java
PriorityQueue<Integer> queue =
    new PriorityQueue<>();
```

```java
queue.offer(5);
queue.offer(1);
queue.offer(3);
```

주요 메서드:

| 메서드         | 역할                      | 시간복잡도 |
| -------------- | ------------------------- | ---------: |
| `offer(value)` | 원소 추가 후 `siftUp`     | `O(log n)` |
| `peek()`       | 루트의 최솟값 확인        |     `O(1)` |
| `poll()`       | 최솟값 제거 후 `siftDown` | `O(log n)` |
| `isEmpty()`    | 비어 있는지 확인          |     `O(1)` |
| `size()`       | 원소 개수 확인            |     `O(1)` |

최대 힙이 필요하면 역순 Comparator를 전달한다.

```java
PriorityQueue<Integer> queue =
    new PriorityQueue<>(
        Comparator.reverseOrder()
    );
```

## 6. 순회 결과가 정렬 순서가 아닌 이유

최소 힙은 부모가 자식보다 작거나 같다는 조건만 보장한다.

```text
        1
      /   \
     4     2
    / \   / \
   8   5 3   7
```

내부 배열은 다음과 같다.

```text
[1, 4, 2, 8, 5, 3, 7]
```

최소 힙 조건은 만족하지만 전체 오름차순은 아니다.

따라서 다음 순회는 정렬 순서를 보장하지 않는다.

```java
for (int value : queue) {
    System.out.println(value);
}
```

정렬된 순서로 처리하려면 `poll()`을 반복해야 한다.

```java
while (!queue.isEmpty()) {
    System.out.println(queue.poll());
}
```

단, `poll()`은 원소를 제거한다. 원본을 유지해야 한다면 큐를 복사한다.

```java
PriorityQueue<Integer> copy =
    new PriorityQueue<>(queue);
```

## 7. TreeSet과 TreeMap

`TreeSet`과 `TreeMap`은 레드-블랙 트리를 이용해 데이터를 정렬된 상태로 관리한다.

레드-블랙 트리는 원소가 추가되거나 삭제되어도 한쪽으로 지나치게 치우치지 않도록 균형을 조정하는 이진 탐색 트리다.

### TreeSet

`TreeSet`은 중복되지 않는 값을 정렬된 상태로 관리한다.

```java
TreeSet<Integer> numbers =
    new TreeSet<>();

numbers.add(5);
numbers.add(1);
numbers.add(3);
numbers.add(3);
```

결과:

```text
[1, 3, 5]
```

### TreeMap

`TreeMap`은 키와 값을 저장하고 키를 정렬된 상태로 관리한다.

```java
TreeMap<Integer, String> students =
    new TreeMap<>();

students.put(3, "철수");
students.put(1, "영희");
students.put(2, "민수");
```

결과:

```text
{1=영희, 2=민수, 3=철수}
```

주요 추가·조회·삭제 작업은 일반적으로 `O(log n)`이다.

## 8. PriorityQueue와 정렬 트리의 차이

```text
PriorityQueue
→ 루트의 최솟값 또는 최댓값을 빠르게 처리
→ 전체 순회 순서는 보장하지 않음
```

```text
TreeSet
→ 중복 없는 값을 전체 정렬 상태로 관리
→ 순회도 정렬 순서
```

```text
TreeMap
→ key-value 저장
→ key를 전체 정렬 상태로 관리
→ 가까운 키나 범위 검색 가능
```

## 9. floor와 ceiling

`floorKey()`는 기준 이하인 키 중 가장 큰 키를 반환한다.

```text
floorKey
→ 기준 이하(≤) 중 가장 큰 키
```

`ceilingKey()`는 기준 이상인 키 중 가장 작은 키를 반환한다.

```text
ceilingKey
→ 기준 이상(≥) 중 가장 작은 키
```

```java
TreeMap<Integer, String> map =
    new TreeMap<>();

map.put(10, "A");
map.put(20, "B");
map.put(30, "C");
map.put(40, "D");

map.floorKey(28);   // 20
map.ceilingKey(28); // 30
```

조건을 만족하는 키가 없으면 `null`을 반환한다.

`TreeSet`에서는 대응하는 `floor()`와 `ceiling()`을 사용한다.

## 최종 요약

```text
최소 힙
→ 부모 ≤ 자식
→ 루트에 최솟값
→ 전체 정렬은 아님

siftUp
→ 삽입한 값을 부모와 비교하며 위로 이동

siftDown
→ 루트 제거 후 마지막 값을 자식과 비교하며 아래로 이동

PriorityQueue
→ 기본 최소 힙
→ offer/poll O(log n), peek O(1)
→ 정렬 순회가 필요하면 poll 반복

TreeSet
→ 중복 없는 값의 정렬 집합

TreeMap
→ key가 정렬된 map

floor
→ 기준 이하 중 가장 큰 값

ceiling
→ 기준 이상 중 가장 작은 값
```
