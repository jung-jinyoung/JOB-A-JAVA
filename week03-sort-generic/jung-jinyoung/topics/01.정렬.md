# 자바의 정렬 방식

## 1. 퀵소트

퀵소트는 배열에서 기준값인 피벗을 선택하고, 피벗을 기준으로 값을 나눈 뒤 각 구간에서 같은 작업을 반복하는 정렬 알고리즘이다.

일반적인 단일 피벗 퀵소트는 배열을 다음과 같이 나눈다.

```text
피벗보다 작은 값 | 피벗 | 피벗보다 큰 값
```

예를 들어 다음 배열에서 피벗을 `4`로 선택하면:

```text
[4, 7, 2, 9, 1, 5]
```

다음과 같이 나눌 수 있다.

```text
[2, 1] | 4 | [7, 9, 5]
```

왼쪽과 오른쪽 구간에서도 다시 피벗을 선택하고 같은 과정을 반복한다.

퀵소트에서 피벗을 기준으로 배열을 여러 영역으로 나누는 작업을 파티셔닝이라고 한다.

## 2. 듀얼 피벗 퀵소트

듀얼 피벗 퀵소트는 피벗을 하나가 아닌 두 개 사용한다.

```text
pivot1보다 작은 값
| pivot1과 pivot2 사이의 값
| pivot2보다 큰 값
```

예를 들어 두 피벗이 `3`과 `7`이라면 값 `5`는 두 피벗 사이의 영역으로 이동한다.

Java의 `Arrays.sort(int[])`는 듀얼 피벗 퀵소트를 중심으로 여러 정렬 전략을 함께 사용한다.

```java
int[] numbers = {5, 2, 8, 1};

Arrays.sort(numbers);
```

결과:

```text
[1, 2, 5, 8]
```

## 3. 안정 정렬과 불안정 정렬

안정 정렬은 비교 결과가 같은 원소들의 기존 순서를 유지하는 정렬이다.

다음 학생들을 점수 기준으로 정렬한다고 가정한다.

```text
정렬 전:
철수(90) → 영희(80) → 민수(90)
```

안정 정렬의 결과는 다음과 같다.

```text
영희(80) → 철수(90) → 민수(90)
```

점수가 같은 철수와 민수의 기존 순서가 유지됐다.

불안정 정렬에서는 다음처럼 두 학생의 순서가 바뀔 수도 있다.

```text
영희(80) → 민수(90) → 철수(90)
```

불안정 정렬이라는 표현은 정렬 결과가 틀린다는 뜻이 아니다. 비교 결과가 같은 원소들의 기존 순서를 보장하지 않는다는 뜻이다.

원시 타입 배열에서는 같은 값의 순서가 바뀌어도 차이를 구분하기 어렵다.

```java
int[] scores = {90, 80, 90};
```

두 개의 `90`이 서로 자리를 바꾸더라도 결과는 다음과 같다.

```text
[80, 90, 90]
```

따라서 원시 타입 배열에서는 안정 정렬의 이점이 크지 않다.

객체는 비교 기준이 같더라도 이름이나 등록 순서 같은 다른 정보를 가지고 있으므로 안정성이 의미를 가질 수 있다.

## 4. in-place 정렬

in-place 정렬은 입력 크기에 비례하는 별도의 결과 배열을 만들지 않고 원본 배열 안에서 원소의 위치를 바꾸며 정렬하는 방식이다.

```java
int[] numbers = {3, 1, 2};

Arrays.sort(numbers);
```

`Arrays.sort()` 호출 후 `numbers` 자체가 변경된다.

```text
호출 전: [3, 1, 2]
호출 후: [1, 2, 3]
```

`Arrays.sort()`는 새로운 배열을 반환하지 않는다.

```java
int[] sorted = Arrays.sort(numbers); // 컴파일 에러
```

원본을 유지하고 싶다면 먼저 배열을 복사해야 한다.

```java
int[] original = {5, 1, 3};

int[] copied = Arrays.copyOf(
    original,
    original.length
);

Arrays.sort(copied);
```

결과:

```text
original = [5, 1, 3]
copied   = [1, 3, 5]
```

in-place라고 해도 재귀 호출 스택과 같은 약간의 보조 공간은 사용할 수 있다. 핵심은 원본 배열 크기에 비례하는 별도의 결과 배열을 만들지 않는다는 것이다.

## 5. TimSort

`String[]`, `Integer[]`, `Student[]`과 같은 객체 배열은 TimSort 계열로 정렬된다.

```java
String[] names = {
    "Charlie",
    "Alice",
    "Bob"
};

Arrays.sort(names);
```

TimSort는 데이터에서 이미 정렬된 연속 구간을 찾는다. 이 구간을 `run`이라고 한다.

```text
[1, 4, 6] [2, 3, 8]
 └ run 1 ┘  └ run 2 ┘
```

TimSort는 이미 정렬된 두 run을 처음부터 다시 정렬하지 않고 병합한다.

```text
run 1: [1, 4, 6]
run 2: [2, 3, 8]

병합 결과:
[1, 2, 3, 4, 6, 8]
```

TimSort는 비교 결과가 같은 객체들의 기존 순서를 유지하는 안정 정렬이다. 병합 과정에서는 임시 저장 공간을 사용할 수 있다.

## 6. 원시 타입과 객체 배열이 다른 정렬 방식을 사용하는 이유

원시 타입 배열과 객체 배열은 다음과 같은 차이가 있다.

### 원시 타입 배열

```java
int[] numbers;
```

- 같은 값끼리 기존 순서를 유지할 이익이 적다.
- 객체 메서드가 아니라 값을 직접 비교한다.
- 적은 추가 메모리와 빠른 값 교환이 중요하다.
- 듀얼 피벗 퀵소트 계열을 사용한다.
- 안정 정렬을 보장하지 않는다.

### 객체 배열

```java
Student[] students;
```

- 비교 결과가 같아도 서로 다른 객체일 수 있다.
- 같은 비교값을 가진 객체의 기존 순서가 의미를 가질 수 있다.
- `Comparable` 또는 `Comparator`를 통해 비교한다.
- 이미 정렬된 구간을 활용하면 객체 비교 횟수를 줄일 수 있다.
- 안정 정렬인 TimSort 계열을 사용한다.

따라서 다음과 같이 정리할 수 있다.

> 원시 타입 배열은 안정성의 실익이 적고 적은 추가 메모리와 빠른 값 교환이 중요하므로 듀얼 피벗 퀵소트 계열을 사용한다. 객체 배열은 같은 비교값을 가진 서로 다른 객체의 순서를 보존하는 것이 중요할 수 있으므로 안정적인 TimSort 계열을 사용한다.

## 7. `Collections.sort()`

`Arrays.sort()`는 배열을 정렬하고 `Collections.sort()`는 수정 가능한 `List`를 정렬한다.

```java
List<Integer> numbers =
    new ArrayList<>(List.of(3, 1, 2));

Collections.sort(numbers);
```

결과:

```text
[1, 2, 3]
```

현재 Java에서는 `Collections.sort()`는 `List.sort()`에 정렬 작업을 위임한다.

```java
Collections.sort(numbers);
```

다음과 같이 직접 정렬할 수도 있다.

```java
numbers.sort(Comparator.naturalOrder());
```

`Collections.sort()`와 `List.sort()`는 안정 정렬을 보장한다.

`List.of()`로 만든 리스트는 수정할 수 없으므로 직접 정렬할 수 없다.

```java
List<Integer> numbers = List.of(3, 1, 2);

Collections.sort(numbers); // 실행 중 예외
```

정렬하려면 수정 가능한 `ArrayList`로 복사해야 한다.

```java
List<Integer> numbers =
    new ArrayList<>(List.of(3, 1, 2));

Collections.sort(numbers);
```

## 8. anti-quicksort 문제

퀵소트가 빠르게 동작하려면 피벗이 배열을 비교적 균등하게 나눠야 한다.

좋은 분할:

```text
10개 → 5개 + 4개
```

나쁜 분할:

```text
10개 → 0개 + 9개
9개  → 0개 + 8개
8개  → 0개 + 7개
```

나쁜 분할이 계속 반복되면 퀵소트의 시간복잡도가 `O(n²)`까지 나빠질 수 있다.

anti-quicksort는 정렬 구현의 피벗 선택 방식을 노려, 계속 불균형한 분할이 발생하도록 의도적으로 구성한 입력이다.

예를 들어 항상 첫 번째 값을 피벗으로 사용하는 단순한 퀵소트에서는 이미 정렬된 배열이 나쁜 입력이 될 수 있다.

```text
[1, 2, 3, 4, 5, 6, 7]
```

다만 실제 Java 구현은 첫 번째 값만 단순하게 피벗으로 선택하지 않으므로, 위 배열이 그대로 Java 정렬에 대한 공격 입력이라는 뜻은 아니다.

## 9. Java의 anti-quicksort 방어 방법

### 여러 값을 표본으로 확인

Java는 한 위치의 값을 무조건 피벗으로 사용하지 않고 여러 위치의 값을 표본으로 확인한다.

이렇게 하면 최솟값이나 최댓값처럼 한쪽으로 치우친 값을 피벗으로 선택할 가능성이 줄어든다.

완벽한 피벗을 보장하는 것은 아니지만 불균형한 분할의 가능성을 낮출 수 있다.

### 같은 값이 많으면 3-way 분할

다음처럼 같은 값이 많은 배열에서는 서로 다른 두 피벗으로 나누는 장점이 적다.

```text
[4, 2, 4, 7, 4, 1]
```

피벗을 `4`로 정하면 다음처럼 세 영역으로 나눌 수 있다.

```text
4보다 작음 = [2, 1]
4와 같음   = [4, 4, 4]
4보다 큼   = [7]
```

피벗과 같은 가운데 영역은 이미 같은 값으로 구성되어 있으므로 추가로 정렬할 필요가 없다.

### 힙 정렬로 전환

피벗을 신중하게 선택해도 나쁜 분할을 완전히 막을 수는 없다.

Java는 퀵소트의 분할이 계속 반복되어 재귀 깊이가 기준을 초과하면 해당 구간을 힙 정렬로 처리한다.

```text
평소:
빠른 퀵소트 사용

불균형한 분할이 계속 발생:
힙 정렬로 전환
```

퀵소트는 나쁜 분할이 반복되면 `O(n²)`까지 느려질 수 있지만, 힙 정렬은 최악의 경우에도 `O(n log n)`을 유지한다.

따라서 Java는 퀵소트의 일반적인 빠른 성능을 활용하면서, 위험한 상황에서는 힙 정렬로 전환해 최악의 성능 저하를 방어한다.

## 최종 요약

```text
Arrays.sort(int[])
→ 듀얼 피벗 퀵소트 중심
→ 불안정 정렬
→ in-place
→ 표본 선택, 3-way 분할, 힙 정렬 전환으로 나쁜 입력 방어

Arrays.sort(Object[])
→ TimSort 계열
→ 안정 정렬
→ 이미 정렬된 run을 찾아 병합

Collections.sort()
→ 수정 가능한 List 정렬
→ 현재는 List.sort()에 위임
→ 안정 정렬 보장
```
