> 오너: B / 마감: 금 23:59 (제출) · 일 23:59 (상호 리뷰 완료)
> 마지막 주차이니 새 개념(JWT)과 마무리 작업이 함께 있습니다. 시간 배분에 주의하세요.

## 학습 목표

- 인증/인가의 기본 흐름을 이해하고 **JWT를 직접 적용**해본다
- 스스로 만든 API가 **테스트와 문서를 갖춘 상태**로 완결된다
- 남의 코드를 읽고 근거 있는 리뷰를 남길 수 있다

## 학습 주제

### 1. 인증/인가 기초

- 인증(Authentication)과 인가(Authorization)의 차이
- 세션 기반 vs 토큰 기반 인증
- JWT 구조 (Header.Payload.Signature), 서명 검증 원리
- Access Token / Refresh Token 개념 (깊은 구현까지는 안 감)

### 2. Spring Security 최소 적용

- `SecurityFilterChain` 기본 구조
- 로그인 → JWT 발급 → 요청마다 토큰 검증하는 흐름
- 비밀번호 해싱(`BCryptPasswordEncoder`)

> 이번 주는 **동작하는 최소 구현**이 목표입니다. Refresh Token 재발급, 권한 세분화 같은 심화는 다음 사이클로 넘깁니다.

> **마지막 주차라 부담이 가장 큽니다.** JWT 토큰 생성/검증 로직은 `jjwt` 같은 라이브러리를 그대로 써도 됩니다 — 서명 알고리즘을 직접 구현하는 게 목표가 아니라, **필터 체인에 어떻게 끼워 넣는지, 인증 실패 시 어떤 응답이 나가는지**를 이해하는 게 목표입니다. 막히면 최소한 로그인 API + 필터 1개만이라도 동작하게 만들고 `retrospective.md`에 못 끝낸 부분을 남기세요.

### 과제 — JWT 인증 적용 + 최종 통합

**요구사항**

- 로그인 API 1개 (`POST /api/auth/login`) — 성공 시 JWT 발급
- 기존 6~7주차 API 중 최소 1개 이상에 **JWT 인증 필터** 적용
- 토큰 없이 접근 시 401, 잘못된 토큰이면 401/403 응답
- 비밀번호는 반드시 해싱 저장
