## 1. 핵심 질문 답변

> 검색한 문장을 붙여넣지 말 것. 본인 문장으로 쓰고, 예시 코드를 곁들이면 좋음.

### Q1. `String`이 불변인 것이 왜 이득인가? (힌트: 캐싱, 해시, 스레드)

같은 내용을 담은 문자열을 사용할때, 이미 생성된 객체를 가져오기만 하면 되고, 해시값을 한번만 생성하고 계속 재사용할 수 있으며, 여러 스레드에서 동시에 사용하더라도 문제가 발생하지 않음

### Q2. 반복문 안에서 `s += x`를 10만 번 돌리면 내부적으로 무슨 일이 일어나는가? 시간복잡도는?

String은 불변이라 + 연산 시 계속해서 새로운 String 객체를 만들고, 그 안에 결과를 붙여넣음  
그 과정에서 엄청난 객체 생성이 이루어지고 시간 및 자원 낭비로 이어짐  
s의 길이는 점점 길어지고, 계속해서 그 s의 내용을 새로운 객체에 붙여 넣을테니 1 + 2 + ... + n = n (n-1)/2  
즉, `O(N^2)`의 시간 복잡도를 가지게 됨

이러지 말고 가변객체인 StringBuilder를 사용하자

```java
void main() {
    String x = "a";

    String s1 = new String();
    for (int i = 0; i < 100000; i++) {
        s1 += x;
    }

    StringBuilder s2 = new StringBuilder();
    for (int i = 0; i < 100000; i++) {
        s2.append(x);
    }
}
```

### Q3. `int` 두 개를 더했는데 음수가 나왔다. 왜 그런가? 어떻게 막는가?

양수가 나와야하는데 음수가 나온 경우 int의 범위를 넘어가면서 부호 비트가 바뀌어서 발생한 오류  
더하기 전 미리 캐스팅을 하여 부호 비트를 침범하지 않도록 비트 개수를 늘리자

```java
int a = 2000000000;
int b = 2000000000;

long c = (long) a + b;
```

## 3. 구현 과제 회고

- 어떻게 설계했는가  
  읽기 쓰기는 모두 기존 BufferedReader, BufferedWriter의 버퍼를 최대한 활용하도록 설계함  
  println () 메서드의 경우 BufferedWriter의 write ()와 flush () 메서드를 상황에 맞게 사용할 수 있도록 println ()과 write ()를 따로 구현함

- 막혔던 지점  
  에러 처리를 제대로 했는지 확실하지 않음  
  뭔가 사용하면서 다양한 케이스를 넣다보면 무조건 한두개는 더 나올거같은 기분...

- JDK 실제 구현과 비교했을 때 다른 점  
  JDK에 구현된 메서드는 오랜 기간 사용하며 쌓여온 데이터를 기반으로 아주 많은 에러 처리가 되어 있음  
  그에 반해 입력 과정에서 에러가 발생하면 어차피 알고리즘 문제는 실패하기 때문에, 에러는 싹다 try catch로 던져버리고, 타입 검증, 정규식 이런거도 다 내다버림  
  확실한 목적성을 가진 메서드와 범용적으로 사용 가능한 메서드의 구현 난이도 차이를 확실하게 알 수 있었던 부분
