## `Scanner` vs `BufferedReader` + `StringTokenizer`

Scanner는 버퍼 크기가 1024 바이트밖에 안됨

```java
public final class Scanner implements Iterator<String>, Closeable {
    private static final int BUFFER_SIZE = 1024;
}
```

그래서 조금만 큰 문자열을 읽으면 계속해서 버퍼를 비워줘야 함  
이 과정이 엄청난 시간을 소요하게 됨

그에 반해 BufferedReader는 버퍼 크기가 8192 바이트

```java
public class BufferedReader extends Reader {
    private static final int DEFAULT_CHAR_BUFFER_SIZE = 8192;
}
```

8배나 버퍼 크기가 커서 훨씬 빠르게 처리 가능함

대신 Scanner에서는 nextInt () 같은 편리하게 단어를 불러올 수 있는 메서드를 지원함  
하지만 범용적으로 사용하는 메서드라 내부적으로 오류를 방지하기 위해 검사하는 로직이 많음  
그로 인해 속도가 느려지는데 우리의 친구 StringTokenizer는 싹다 냅다 문자열로 읽어서 그런게 없음  
알고리즘에서 많이 사용하자

## `System.out.println` vs `BufferedWriter`

println은 매번 실행할때마다 I/O를 호출하고, 심지어 thread-safe 로직도 있어서 호출할때 잡다한 작업이 많이 들어감  
그에 반해 BufferedWriter는 BufferedReader처럼 버퍼에 넣어두고 한번에 출력해 이런 문제가 없음  
알고리즘에서 사용해보면 시간 차이가 명확하게 나는 것을 알 수 있음
