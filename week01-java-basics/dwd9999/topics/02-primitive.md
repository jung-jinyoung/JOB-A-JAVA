## `int` / `long` 범위, 언제 `long`으로 승격해야 하는가

int 범위: `-2^31` ~ `2^31-1`  
long 범위: `-2^63` ~ `2^63-1`

int는 4byte, long은 8byte로 이루어짐  
1byte는 8bit 이므로, int는 총 32bit, long은 총 64bit

여기서 int는 `2^31` 범위, long은 `2^63` 범위까지만 사용 가능한 이유는 맨 앞 비트가 이 숫자가 음수인지 양수인지 나타내는 비트이기 때문!  
그래서 본인의 범위를 넘어가면 **맨 앞 부호 비트가 침범**당하고, 양수가 음수로 바뀌어버리는 결과가 나오는 것

그럼 언제 long으로 승격해야 할까?  
문제가 어떤 것을 원하는 문제인지는 잘 모르겠지만, 개발 과정에서 int와 long을 구분짓는 것은 **해당 숫자가 long 범위로 넘어갈 가능성**의 여부  
평소에는 int 범위 내에서 사용되더라도, 만에하나 long의 범위로 넘어갈 가능성이 조금이라도 있다면 미리 long으로 선언해두는 것이 편함

만약 해당 숫자는 int 범위 내에서만 사용되나, 그 숫자가 사용되는 연산이 long 범위로 넘어갈 것 같다면 캐스팅을 사용해야 함  
캐스팅이란 그 변수 앞에 `(자료형)`을 붙여서 강제로 자료형을 변경하는 것

```java
int a = 2000000000;
int b = 2000000000;

long c = (long) a + b;
```

이런식으로 연산이 일어나기 전 강제로 long으로 변환 후 진행해야 오버플로우가 발생하지 않음

## 정수 나눗셈, 형변환 시 손실

int, long 등 정수를 담는 자료형은 나눗셈을 했을때 그 결과 또한 정수만 담을 수 있으므로 냅다 소숫점을 버려버림  
그래서 미리 캐스팅을 해둬야 함

```java
int a = 3;
int b = 2;

int c = a / b; // c는 1
double d = (double) a / b; // d는 1.5
```

그리고, 캐스팅 과정에서 더 작은 자료형으로 캐스팅을 하면 그대로 자리가 맞지 않는 비트를 다 버려버림  
double에서 int로 바꾸면 소수점을 다 버리고, long에서 int로 바꾸면 아래쪽 32비트만 남기고 또 다 썰림  
형변환은 항상 주의하자

## `double` 부동소수점 오차 → 비교 시 주의

소수점은 정수 부분과 소수 부분으로 나뉘는데, 정수와 소수에 각자 몇 비트씩 할당해야 하는지 애매해짐  
그래서 나온 방식이 부동소수점  
부동소수점은 123.45같은 수를 1.2345 * 10^2 처럼 표현함
```
0.1 (2진수: 0.00011 0011 0011...) = 1.1 0011 0011 0011 ... * 2^-4
10.1 (2진수: 1010.00011001100110011...) = 1.01000011001100110011... * 2^3
2234.23 (2진수: 100010111010.0001110101...) = 1.0001011101000011101010... * 2^11
```
말 그대로 소수점 위치가 떠다니기 때문에 부동소수점

메모리는 숫자를 어쩔 수 없이 비트로 저장함  
그래서 소수점도 비트로 표현해야 하고, 소수점을 비트로 표현하기 위해서는 `2^-1=0.5`, `2^-2=0.25`,`2^-3=0.125`, ... 등 한정된 소수점들의 합으로 표현해야 함  

이 방법으로 표현하려고 하다 보면 표현 못하는 소수점들이 생김  
예를 들어 0.1은 0.000110011001100110011... 이렇게 됨  
결국 비트를 무한하게 할당할 수 없으므로 특정 시점에 절삭하고 근사치로 저장해야 함  

사실 부동소수점때문에 발생하는 문제는 아닌데, 고정소수점이 너무 범위가 쓰레기라 부동소수점만 쓰다보니 오명까지 같이 쓴 것;;
