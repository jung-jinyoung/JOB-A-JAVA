## Week 1 Review — 2주제: 원시타입과 오버플로우

### 학습 내용
- `int`/`long`의 오버플로우 발생 원리 (2의 보수 표현, 범위 초과 시 비트가 잘리는 과정)
- `int` 연산 결과를 `long`에 대입해도 오버플로우가 막히지 않는 함정과, 연산 자체를 캐스팅하는 올바른 방법
- 정수 나눗셈(`int / int`)의 버림 동작과 `(double)` 캐스팅 위치에 따른 결과 차이
- `double → int` 형변환 손실 (반올림이 아닌 버림, 범위 초과 시 clamping)
- `double`의 부동소수점 오차 원인과, 이를 피하는 `BigDecimal` 사용법

### 이해한 핵심 개념
- `int`는 32비트, `long`은 64비트로 크기가 고정되어 있고 둘 다 2의 보수 방식으로 값을 표현한다. 범위를 넘는 계산을 해도 예외가 발생하지 않고, 넘치는 비트가 잘려나간 채로 **조용히 다른 값(종종 음수)** 이 반환된다.
- `long c = a + b;`처럼 **대입받는 변수의 타입만 바꿔서는 오버플로우가 막히지 않는다.** 자바는 연산에 참여하는 **피연산자의 타입**을 기준으로 계산 방식을 정하기 때문에, `a`와 `b`가 둘 다 `int`면 `a + b` 연산 자체가 이미 `int` 범위 안에서 끝나버린다. 막으려면 `(long) a + b`처럼 **피연산자 중 하나를 미리 캐스팅**해서 연산 자체가 `long` 범위에서 일어나게 해야 한다.
- `int / int`는 결과가 실수여야 할 상황에서도 **몫만 남기고 나머지를 버린다.** 이때 `(double) 7 / 2`(먼저 캐스팅 후 나눗셈)와 `(double) (7 / 2)`(나눗셈 먼저 끝낸 후 캐스팅)는 각각 `3.5`와 `3.0`으로 **결과가 완전히 다르다** — 괄호 위치가 계산 순서를 바꾸기 때문.
- `double`을 `int`로 좁히는 캐스팅은 반올림이 아니라 소수점 이하를 **그대로 버린다.** 또한 `int` 범위를 넘는 값을 캐스팅하면 오버플로우처럼 비트가 잘리는 게 아니라 `Integer.MAX_VALUE`/`MIN_VALUE`로 **고정(clamping)** 된다 — 오버플로우와는 다른 별도 규칙.
- `0.1 + 0.2`가 `0.3`이 안 되는 이유는 이진수로 `0.1`을 정확히 표현할 수 없어서 생기는 오차 때문이다. 금액처럼 정확도가 중요한 값을 `double`로 `==` 비교하면 실무에서 결제 오류 등으로 이어질 수 있어 위험하다. `BigDecimal`은 값을 이진수 근사치가 아니라 10진수 그대로 저장해 이 문제를 피하며, 반드시 **문자열로 생성**(`new BigDecimal("0.1")`)해야 하고 연산은 `add`/`subtract` 같은 메서드로 한다.

### 어려웠던 부분
- 이번 세션에서는 사전 예측이 대부분 맞아서 크게 막힌 지점은 없었음. 다만 아래 두 가지는 예측 없이 봤다면 실수하기 쉬운 지점으로 기록해둠:
    - `long` 승격이 대입 시점이 아니라 **연산에 참여하는 피연산자의 타입**에 좌우된다는 것
    - `(double) 7 / 2`와 `(double) (7 / 2)`가 괄호 위치 하나로 `3.5`/`3.0`으로 갈린다는 것

### 새롭게 알게 된 Java 특징
- 타입 승격은 **선언된 변수 타입이 아니라 연산 시점의 피연산자 타입**을 기준으로 일어난다.
- Narrowing casting(`double → int`)은 자바 언어 명세상 범위 초과 시 **clamping**하도록 정의되어 있어, 오버플로우(비트 잘림)와는 별개의 동작이다.
- 숫자 리터럴에 `_` 구분자를 쓸 수 있다 (`2_000_000_000`) — 컴파일러가 가독성을 위해서만 두고 무시함.
