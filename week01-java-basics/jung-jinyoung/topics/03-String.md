## Week 1 Review — 3주제: String

### 학습 내용
- `String`이 불변인 이유 3가지 (캐싱/해시/스레드 안전성)
- String Constant Pool과 `new String()`의 차이, `==` vs `.equals()`
- `+=` 반복의 비용(O(n²))과 `StringBuilder`의 구조(capacity, 배열 재할당) 및 기본 사용법

### 실습 코드
- [`src/practices/StringCheck.java`](../src/practices/StringCheck.java)

### 이해한 핵심 개념
- `String`은 한번 만들어지면 내용을 바꿀 수 없고, `a = a + " world"`처럼 재대입해도 실제로는 새 문자열을 Heap에 만들고 이름표만 옮기는 것이다. 이 불변성 덕분에 세 가지 이득이 생긴다: ① 여러 변수가 같은 문자열을 안전하게 공유(캐싱)할 수 있고, ② `hashCode()`를 한 번 계산해 캐싱해도 항상 유효하며, ③ 값이 안 바뀌니 여러 스레드가 동시에 읽어도 안전하다.
- 문자열 리터럴(`"hello"`)은 **String Constant Pool**에서 재사용되지만, `new String("hello")`는 강제로 별도 객체를 Heap에 만든다. `==`는 "같은 자리(주소)인가"를 비교하고, `.equals()`는 "내용(문자)이 같은가"를 비교한다 — 저장 위치가 상황에 따라 달라질 수 있으므로 String 비교는 반드시 `.equals()`를 써야 한다.
- `int` 같은 원시타입은 Stack에 값 자체가 담기므로 `==`가 곧 값 비교이지만, `String`은 참조타입이라 Stack에는 Heap 주소만 담긴다. 그래서 `==`의 의미가 원시타입과 참조타입에서 다르게 동작한다.
- `s += x`를 반복하면 String이 불변이라 매번 기존 내용을 전부 복사한 새 문자열을 만든다. 반복이 진행될수록 복사량이 늘어나 총 작업량이 `n²`에 비례한다(시간복잡도 O(n²)).
- `StringBuilder`는 가변이며 내부에 여유 공간(capacity)을 가진 배열을 두고 그 자리에 직접 추가한다. 배열이 꽉 차면 자르거나 초기화하는 게 아니라 **더 큰 배열을 새로 만들어 기존 내용을 복사**하는 방식으로 확장한다. 이 재할당이 매번이 아니라 꽉 찰 때만 일어나기 때문에 전체 시간복잡도가 O(n)이 된다.
- `StringBuilder`의 주요 메서드: `append`, `insert`, `delete`, `deleteCharAt`, `reverse`, `charAt`, `setCharAt`, `length`, `toString`. 대부분 자기 자신을 반환해 메서드 체이닝이 가능하다.

### 어려웠던 부분
- 원시타입(`int`)도 불변이라는 점을 헷갈려, String과 원시타입의 차이를 "가변성"으로 잘못 짚었던 지점이 있었음 — 실제 차이는 **Stack에 값 자체가 담기는지, Heap 주소가 담기는지**였음.
- `String`이 가변이었다면 생기는 문제를 처음엔 "메모리 누수"로 답했는데, 실제로는 누수가 아니라 **공유된 값이 한쪽 수정으로 다른 변수까지 오염되는 문제**였음.
- `s += x`가 매 반복마다 새 문자열을 만드는지 묻는 질문에서 답변이 여러 차례 엇나가, 불변성 원리를 다시 짚고 나서야 정리됨.
- `StringBuilder`의 배열이 꽉 찼을 때의 동작을 "자르거나 초기화"로 잘못 예측함 — 실제로는 더 큰 배열로 통째로 교체하고 기존 내용을 복사하는 방식.

### 새롭게 알게 된 Java 특징
- String Constant Pool은 리터럴만 재사용 대상이고, `new String(...)`은 이 재사용 규칙을 의도적으로 무시하는 문법이다.
- `StringBuilder`는 기본 생성자로 만들면 처음부터 16칸의 여유 공간을 확보해두고, 꽉 차면 대략 "기존 용량 × 2 + 2" 크기로 재할당한다(JDK 버전에 따라 세부 공식은 다를 수 있음).
- `StringBuilder(int)` 생성자로 초기 용량을 미리 지정하면 재할당 자체를 없앨 수 있다.
- `StringBuffer`는 `StringBuilder`와 기능은 동일하고 스레드 안전성(동기화) 여부만 다르다 — 혼자 쓰는 경우 `StringBuilder`가 기본 선택.
