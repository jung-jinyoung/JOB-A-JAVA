## 1. 스터디 목표

### 최상위 목표

> **8주 뒤, "자바를 안다"고 말할 수 있고 스프링 REST API를 스스로 만들 수 있는 상태가 된다.**

### 세부 목표

| #   | 목표                                                  | 확인 방법                                         |
| --- | ----------------------------------------------------- | ------------------------------------------------- |
| G1  | 자바 표준 라이브러리의 **내부 동작을 설명**할 수 있다 | 매주 핵심 질문 3개에 글로 답변                    |
| G2  | 자료구조를 **직접 구현**해본 경험이 있다              | `MyHashMap` 등 구현 과제 통과                     |
| G3  | 알고리즘 문제를 **자바로** 시간 초과 없이 푼다        | 8주 누적 20문제 이상 (1-4주 주 3개, 5-8주 주 2개) |
| G4  | DI / IoC가 **왜 필요한지** 체감으로 안다              | 순수 자바 코드를 스프링으로 직접 이식             |
| G5  | **CRUD REST API**를 설계·구현·테스트할 수 있다        | 6~7주차 API + 테스트 코드                         |
| G6  | 남의 코드를 읽고 **의미 있는 리뷰**를 남길 수 있다    | PR당 질문/제안 1개 이상                           |

## 3. 진행 규칙

### 주간 사이클

스터디 전원의 대면/비대면 시간대가 안 맞으므로 **모임 대신 파일 제출 마감으로 진행**합니다.

> 아래는 예시입니다. 각자의 사이클에 맞춰 1주일 안으로 진행해주세요

| 시점         | 할 일                                         |
| ------------ | --------------------------------------------- |
| 월 ~ 목      | 각자 학습 (알고리즘 문제는 매일 등록됨)       |
| **금 23:59** | 학습 정리(`notes.md`) + 과제 코드 **PR 등록** |
| 토 ~ 일      | 다른 팀원 PR **리뷰**                         |
| **일 23:59** | 승인 → 머지                                   |

### PR 규칙

- 브랜치명: `week01/{이름}` (예: `week02/jung-jinyoung`)
- **본인 PR 셀프 머지 금지**
- **최소 1명 승인(Approve)** 후 머지
- 승인자는 반드시 **질문 1개 또는 개선 제안 1개**를 남긴다 → `LGTM` 단독 승인 금지
- 리뷰는 코드뿐 아니라 `notes.md`의 **핵심 질문 답변**도 대상

### 진행 담당

이번 스터디는 **알고리즘 문제 출제 + 주차 README 작성**을 한 명이 고정으로 맡습니다. (별도 로테이션 없음)

- 단, **PR 상호 리뷰가 필수**입니다
- 각 주차 README와 알고리즘 문제는 순차적으로 업데이트됩니다

```
│   │   ├── topics/                # (선택) 주제별 상세 정리, 01-xxx.md 형식
│   │   ├── src/                 # 구현 과제
│   │   └── algorithm/           # 알고리즘 풀이
│   ├── dwd9999/

├── week02-hash-collections/
└── ...
```

- 개인 폴더명은 **영문 소문자 통일** (`jung-jinyoung`, `dwd9999`, `krozv`)
- 각 주차 README는 **진행 담당이 관리**, 개인 폴더는 **본인만 수정**
- 남의 폴더를 건드리는 커밋은 리뷰에서 반려
